# 美国单实例代理运维说明

> 本文保留原实例的历史验收记录，地址、SSH 别名与本机用户路径已替换为示例，不是新用户的默认参数。新部署从 [Codex 技能](../skill/vps-proxy-builder/SKILL.md) 开始。2026-08-31 仓库入口已移除个人默认值并加入 `preflight.py`；本次只改仓库，没有重新部署原实例。完整部署需显式配置本人的参数、验证新非 root SSH 会话并确认主机变更/CA 条款；监控默认保留。

最近复验：2026-08-31（Asia/Shanghai）；Trojan TCP 10443 上线，家庭电脑 100/100 请求通过，原两个节点复验通过。晚高峰与 ChatGPT 浏览器体验尚需用户确认。

## 当前架构

这是一套单台 Google Cloud 美国实例的三协议方案，最终出口始终是美国，不会因为节点名、
SNI 或 Cloudflare 变成日本或新加坡出口。

下表为迁移后的实际配置。此次只移动 Trojan，保留 Hysteria UDP 443、REALITY TCP 2053 及原凭据；
没有安装、升级或重建整套服务，Hysteria 进程保持不变。

| 地址或端口 | 实际用途 |
| --- | --- |
| `us1.example.com:2053/TCP` | Xray VLESS + REALITY + XTLS Vision |
| `us1.example.com:443/UDP` | Hysteria2 |
| `us1.example.com:10443/TCP` | Xray Trojan + TLS；未认证流量仅回落到本机静态 Nginx |
| `us1.example.com:80/TCP` | Let's Encrypt HTTP-01 验证和 HTTPS 跳转 |
| `us1.example.com:8443/TCP` | Nginx 备用 Clash YAML 与 URI/Base64 显式订阅 |
| `sub.example.com` | Cloudflare Worker 主聚合订阅（Clash YAML 或通用 URI/Base64） |

`us1.example.com` 是 DNS-only，节点数据不经过 Cloudflare CDN。Cloudflare 只承载订阅接口；
Worker 仅接受精确令牌路径，从私有 KV 分别读取 Clash YAML 与通用 URI/Base64 两份配置，并返回 `Cache-Control: no-store`。

服务器使用原生 systemd，Docker 保留但没有运行容器：

- Xray 同时提供 Trojan TLS（TCP 10443）与 VLESS + REALITY（TCP 2053）：Trojan fallback 为
  `127.0.0.1:8080` 本机静态 Nginx，REALITY TLS target 为 `127.0.0.1:8443` 本机 Nginx TLS。
- Hysteria2 `v2.12.1`，UDP 443，masquerade 代理到 `127.0.0.1:8080` 本机静态 Nginx。
- Nginx、Certbot、vnstat、nftables 均已启用。
- BBR、`fq` 和 TCP MTU 探测已启用。
- Google Ops Agent 已停用并 mask，Guest Agent 与 OSConfig 未改动。

## 订阅格式与客户端兼容

同一主统一入口按 `target=clash` / `target=v2ray` 或客户端 User-Agent 选择响应格式；不能让一次
HTTP 响应同时既是 YAML 又是 Base64。因此 `clash.yaml` 和 `v2ray.txt` 两个显式入口始终保留，
作为不发送或发送未知 User-Agent 的客户端后备。

- Clash YAML：包含 Hysteria2、Trojan、REALITY 三节点，以及策略组、规则和自动切换。
- 通用 URI/Base64：解码后恰为三条 URI，适合支持该 URI 格式的新客户端。
- 兼容边界：不能保证旧版 V2Ray Core 支持 Hysteria2 或 REALITY；只支持旧 Core 的客户端可能只能导入
  Trojan，或应改用支持这些协议的现代客户端。

订阅地址本身是敏感凭据，不写入仓库、日志或报告。需要重新查看时，在服务器执行：

```bash
sudo cat /etc/proxy-stack/subscription-urls.txt
```

## Clash 配置

Windows 上的 Clash Verge 已新增远程订阅 `clash.yaml`，自动更新已开启，导入时没有切换或覆盖
原有的当前配置。需要使用时，在 Clash Verge 的“配置/Profiles”页选中它；也可以在界面中把
这个订阅重命名为“Google Cloud US”。

订阅内包含：

- `US-Hysteria2`：一般网络下的首选节点。
- `US-Trojan`：TCP 10443 的 TLS 兼容线路，已验收并同步订阅。
- `US-Reality`：UDP 受限时的 TCP 备用节点。
- `US-Auto`：依次尝试 Hysteria2、Trojan、REALITY。
- `Proxy-Select`：默认使用 `US-Auto`，也可手动指定协议。
- `ChatGPT`：固定使用 `US-Auto`；规则覆盖 OpenAI 登录、网页、静态资源、文件、WebSocket、
  Codex 和 Voice 相关域名。

国内域名和 IP 直连，其他流量默认使用代理；DNS 使用 Fake-IP，国内解析直连，境外解析跟随代理。

节点密钥和订阅令牌只保存在 `/etc/proxy-stack/secrets.env`，权限为 `0600 root:root`。

## 日常检查

连接服务器：

```powershell
ssh my-proxy-vps
```

检查服务与端口：

```bash
systemctl status xray hysteria-server nginx proxy-firewall vnstat certbot.timer
sudo ss -lntup
sudo nft list chain inet proxy_guard input
```

查看最近日志：

```bash
sudo journalctl -u xray --since "30 minutes ago" --no-pager
sudo journalctl -u hysteria-server --since "30 minutes ago" --no-pager
sudo journalctl -u nginx --since "30 minutes ago" --no-pager
```

Hysteria2 在部署、证书续期或人工重启窗口内出现一次 `transport closed` 属于服务重启的预期现象；
只有在非重启窗口持续出现、并伴随客户端失败时才作为故障升级处理。

查看流量统计和资源：

```bash
vnstat
free -h
df -h /
```

验证配置和证书续期：

```bash
sudo /usr/local/bin/xray run -test -config /etc/xray/config.json
sudo nginx -t
sudo certbot renew --dry-run --no-random-sleep-on-renew
```

证书续期成功后，deploy hook 会同步 Xray 与 Hysteria 的受限证书副本，重启 Xray 与 Hysteria2 并重载 Nginx。

## 更新与恢复

仅将 Trojan 从 443 改到 10443 时，不应直接执行下方完整部署：完整部署会下载软件并重建、重启两个代理服务。
应使用单独的最小迁移及回滚流程，先核对原 Hysteria2/REALITY，再验收 10443；通过后再确认主备订阅同步。
`XRAY_PORT` 默认仍为 2053，拒绝 22、80、443、8080、8443、10443，以避免占用 SSH/Nginx/Trojan 或重新打开 TCP 443。

部署脚本可重复执行，但同一时刻只允许一个实例运行：它会在创建备份、安装软件、写入凭据或变更服务前，
对 `/var/lock/proxy-stack-bootstrap.lock` 取得非阻塞 `flock`。若已有部署在运行，第二个实例会明确退出且不作任何更改；
等待前一个进程结束后再重试。锁文件本身会保留作为审计标记，进程退出时文件描述符自动释放锁，因此不要手工删除它。

获得锁后，脚本会把现有配置、`firewall.nft`、整个订阅目录以及当前 Xray/Hysteria
二进制备份到 `/root/proxy-stack-backup-<UTC时间>-<随机后缀>`，保留已经存在的随机凭据，再校验下载并重建服务配置。

当前不要只上传单个 Bash 文件运行。按 [部署参考](../skill/vps-proxy-builder/references/deployment.md) 先填本人 `.env`（含 `VPS_ADMIN_USER`），完成真实 SSH 验证和授权后：

```powershell
pwsh ./scripts/vps-proxy.ps1 preflight -AdminSshVerified -HostChangesApproved -AcmeTosAccepted
pwsh ./scripts/vps-proxy.ps1 deploy -AdminSshVerified -HostChangesApproved -AcmeTosAccepted
```

入口会同时传输 `server-bootstrap.sh` 与 `preflight.py`。不用 PowerShell 时也必须传这两个文件；不要用旧命令绕过门禁。上面的 `deploy` 仍是完整变更，不用于现有节点的日常检查。

若命令提示已有部署占用锁，不要并发重试，也不要删除锁文件；等当前部署进程结束后重新执行即可。若脚本提示系统没有 `flock`，应先停止并补齐该基础工具，而不是绕过互斥保护。

如果只是同机重跑且凭据没有轮换，主订阅令牌不变。同步时要把
`/var/lib/proxy-subscription/clash.yaml` 上传为 Cloudflare KV 的 `clash-config`，并把
`/var/lib/proxy-subscription/v2ray.txt` 上传为 `v2ray-config`；备用订阅直接读取服务器上的新文件。
使用 root-only 临时目录复制、上传后删除，不要把订阅正文输出到终端。Worker 的可部署源码在
`cloudflare-worker/`。

部署前应先比较 Worker 与 8443 备用入口的同格式内容哈希。服务器备份中的旧
`var/lib/proxy-subscription` 是恢复 KV 的内容源；它不会自动备份 Cloudflare。覆盖 KV 前，在安装了
锁定依赖的本机用当前用户独占、Git 忽略的目录保存两个旧 key，例如以 `umask 077` 创建
`.local-backups/kv-<时间>`（root-only 或当前用户独占）后，执行 `npm exec -- wrangler kv key get` 分别重定向到两个文件，
不在终端显示正文。恢复时将服务器备份中的两份订阅文件重新上传到对应 KV key；Worker 则使用 Git
中的上一已知版本重新部署，或在 Cloudflare 控制台回退到前一 Worker 版本。不要假设部署脚本会备份
Cloudflare 的 KV、secret 或 Worker。

8443 的精确令牌路径现在关闭 access log，避免新请求把令牌写入日志。旧 Nginx 日志仍可能保存历史
路径，应按 root-only 敏感数据处理：只统计是否存在该类路径，绝不显示、复制或放宽日志权限。为保持
已有客户端可用，本次不自动轮换备用令牌；若日志已被不可信主体读取，应按疑似泄漏流程手工轮换。

### Xray Trojan 升级边界

Xray `v26.3.27` 的 classic Trojan transport 会给出弃用警告；本次固定版本的 10443 已通过家庭电脑请求测试。不要因为该
警告盲目升级或替换协议。任何升级前都应保留旧二进制与配置回滚点，用 root-only 临时客户端进行
配置 test 和真实 Trojan 请求；两者通过后才允许切换。

更换公网 IP 后需要同时更新：

1. Cloudflare 中 `us1.example.com` 的 DNS-only A 记录。
2. 本机 `C:\Users\vps-user\.ssh\config` 的 `HostName`。
3. 等 DNS 生效后重新跑连通性、三个协议、聚合订阅和 ChatGPT 浏览器验收。

如果恢复到一台全新的实例，脚本会生成全新的令牌；此时必须同步更新 Worker secret、KV 内容，
然后重新导入新的订阅地址。不要把 `/etc/proxy-stack/secrets.env` 发到聊天、网盘或代码仓库。

## 安全边界

- 主机 nftables 默认丢弃入站，只允许 TCP 22/80/2053/8443/10443、UDP 443、必要 ICMP/DHCP 和已建立连接；TCP 443 新连接不再放行。
- TCP 10443 和 TCP 2053 都对新连接做全局保护；Xray 文件描述符上限为 8192。
- SSH 禁止密码和 root 登录，认证尝试限制为 3 次；22 端口按来源 IP 限制为每分钟 30 个、突发 20 个新连接。
- Xray 与 Hysteria 的出站 ACL 禁止回环、私网、链路本地、GCP Metadata 和 TCP 25。
- 20201、20202 不监听；公网复验也无法连接。
- `sub.example.com` 错误路径返回 404，主订阅与备用订阅使用不同随机令牌。
- Cloudflare 不参与节点流量，也没有使用 WARP 伪造出口国家。

Google Cloud 控制面的防火墙和预算需要账号级权限。当前 VM 服务账号没有 Compute/Billing 管理权限，
所以本次只能完成主机防火墙，不能替你创建 Billing 预算。请在 Google Cloud 控制台的
“Billing → Budgets & alerts”中创建项目范围的每月 100 美元 alerts-only 预算，建议阈值为
50%、90%、100%。预算告警只负责通知，不是消费硬上限。官方说明：
[Create, edit, or delete budgets and budget alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets)。

- 需要撤回本次迁移时，把该脚本传到服务器，执行 `sudo python3 <脚本路径> rollback /root/proxy-trojan-port-EXAMPLE`。随后将备份目录内 `clash`、`v2ray` 内容分别重新写入 Cloudflare 的 `clash-config`、`v2ray-config`。这会回到受流量影响的旧 Trojan 443，不保证旧 Trojan 可用；原两个节点配置仍保留。

## 2026-08-25 连接风暴事件

故障时 TCP 443 有约 7,948 条已建立连接，Xray 打开约 26,154 个文件描述符，监听队列满；
实例负载一度达到 22.90，SSH 和代理均明显卡顿。`vnstat` 从 8 月 12 日至处置时记录约
154.4 GB 入站、144.6 GB 出站。大量不同的中国公网来源以及约三倍于入站连接数的 Xray
描述符，符合 REALITY 未认证 fallback 被批量当作外部中继使用的特征。

处置时完成了以下操作：

- 重启实例清空不可中断进程和旧连接表。
- 轮换 UUID、REALITY 密钥、Hysteria 密码和两个订阅令牌；旧 Worker 路径返回 404。
- REALITY 从 TCP 443 移到 TCP 2053，旧 TCP 443 在主机防火墙关闭。
- REALITY 未认证 fallback 从外部 `www.gstatic.com` 改到本机 Nginx 8443，消除未认证外发带宽。
- 增加 TCP 2053 全局新连接保护和 Xray 文件描述符上限。
- 修正 SSH 全局限速为按来源 IP 限速。

处置后服务器负载回落到接近 0，Xray 仅约 11 个文件描述符；两个节点和自动故障切换均重新实测通过。
这是 2026-08-25 的历史订阅轮换记录：当时的旧订阅不能再更新，需要在 Clash Verge 中选择新导入的 `clash.yaml`。
