# Trojan 残余加固计划

## 目标

处理 Trojan 与聚合订阅主计划唯一复审留下的三个阻断项，使代理服务在系统重启时严格依赖主机防火墙、回滚包包含防火墙 helper，并消除 REALITY fallback 的最后一处错误文档。

## 全局约束

- 不轮换或输出任何 UUID、密码、私钥和订阅令牌。
- 不修改协议、端口、节点顺序、Cloudflare Worker 或 KV 内容。
- Xray 与 Hysteria2 在任何系统启动路径中必须等待 `proxy-firewall.service` 成功；防火墙失败时代理不得启动。
- 保持当前 TCP 443 Trojan、UDP 443 Hysteria2、TCP 2053 REALITY。
- 重部署使用 `ROTATE_SECRETS=0`，运行时验证不得停用正在生效的防火墙。
- 仓库和 worklog 不记录实际 IP、凭据或完整订阅 URL。

## Task 1：systemd、防火墙回滚与文档闭环

1. 修改 systemd unit：`proxy-firewall.service` 明确位于 `xray.service`、`hysteria-server.service` 之前；两个代理 unit 对防火墙建立 `Requires` 与 `After` 依赖，使重启和冷启动均 fail-closed，且无依赖循环。
2. 自动备份清单加入 `/usr/local/sbin/proxy-firewall`，与 unit 和 `firewall.nft` 一起构成完整防火墙回滚包。
3. 静态测试验证 unit 依赖、启动顺序、helper 备份；继续验证脚本内不在防火墙 ready 前启动代理。
4. 修正《美国单实例代理整体方案》：本机 8080 只供 Trojan fallback 与 Hysteria2 masquerade，REALITY TLS target 为 8443。
5. 新建中文 worklog，记录为什么需要 systemd 级依赖而不仅是部署脚本顺序。
6. 运行 Worker 测试、仓库全量校验和 diff 检查并提交。
7. 以 `ROTATE_SECRETS=0` 重部署；验证凭据哈希前后相同、`systemd-analyze verify` 和 `systemctl show` 的依赖关系、三个服务 active、TCP/UDP 监听、防火墙规则、最新备份含 helper/rules/unit、真实 Trojan HTTP 204。
8. 审查发现曾发生并发部署：在任何备份或系统修改前增加非阻塞单实例锁，冲突时明确退出；备份目录使用唯一随机后缀。该补充只修改部署工具，使用临时目录做并发行为测试，不重复上线部署。

## 回滚

若 unit 验证或代理请求失败，使用本次部署产生的新备份恢复 `proxy-firewall` helper、unit、规则和代理 unit，先校验并启动防火墙，再恢复代理服务；不恢复或轮换凭据。
