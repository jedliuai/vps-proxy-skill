# 诊断与恢复：把踩过的坑变成判断依据

先定位故障层：SSH → 主机资源 → DNS/证书 → 云/主机防火墙 → 服务 → 逐协议 → 订阅 → 客户端 → 用户网络。先做只读对照，不在没有证据时升级、轮换、换 IP 或叠加链路。

## 常见症状与最小处理

| 症状 | 先看什么 | 有证据后怎么做 / 不要做什么 |
| --- | --- | --- |
| SSH timeout | 公网 IP、云安全组、主机 firewall、sshd 监听、提供商控制台、是否 root 被禁用 | 用保留控制台恢复访问；不反复猜密码、不直接清空防火墙 |
| SSH host-key 改变 | 控制台指纹、实例/IP 是否重建 | 确认身份再更新该主机记录，不批量删除 known_hosts |
| ACME 失败 | A/AAAA/CAA、DNS-only、公网 TCP80、Nginx webroot、时钟、CA 错误 | 修确定原因后有限重试；不连续生产签发、不跳过 TLS 验证 |
| Hysteria 无法读证书 | 服务 User/Group、目录 execute 权限、0640副本、续期 hook | 复制到各服务组的 certs，目录0750，不给私钥全局可读 |
| HY2 不通、TCP 节点通 | UDP443 两层防火墙、用户网络是否限UDP | 保留 TCP 备用，不能因 TCP443 关闭就开放它“修UDP” |
| 显示 active 但客户端不通 | 真实认证请求、TLS/SNI/UUID/端口、客户端版本 | 分协议测；本机成功不足以宣布公网可用 |
| 新订阅依旧是旧节点 | 服务器/Worker/备用/客户端同格式哈希 | 更新 remote KV 两个 key，再刷新客户端；Worker deploy 不同步 KV |
| 聚合链接导入失败 | UA、target、返回内容类型、核心支持 | 用显式 `clash.yaml` 或 `v2ray.txt`；未知 UA 默认 Base64 |
| 偶尔更新订阅才恢复 | 内容是否真的变化、重载日志时间线、DNS与长连接 | 内容相同可能是重载修连接状态；别当作“节点定时过期” |
| 服务器卡，怀疑 Codex | CPU时间/RSS/available内存/OOM/disk/FD/ss连接数 | 证明资源原因再处理；仅安装 CLI 并不等于占满服务器 |
| 某个端口连不上，SSH正常 | SYN计数、nft限速命中、监听队列、云策略 | 先止损与最小端口迁移，保留原节点；别用全局放行代替诊断 |
| ChatGPT 命令行403 | challenge header、真实浏览器表现 | 人机验证不等于IP封禁；不能承诺换IP就解决 |
| 升级警告但目前可用 | 固定版本的官方说明、安全公告、兼容测试 | 不因警告盲目升级；需要升级先保留旧二进制与配置并独立实测 |
| 部署被锁拒绝 | 前一个部署 PID/阶段 | 等它退出再判断，不删除 flock 文件、不并发执行 |
| check 脚本在 macOS 报错 | 是否缺 Windows `Test-NetConnection` | 直接以 SSH 和该平台 TCP/真实客户端测试替代，不在 VPS 改配置 |

## 案例1：未认证流量变成对外中继

若 TCP 入站连接、Xray 文件描述符和额外上游连接同时异常增长，检查未认证 REALITY fallback 是否正在外发，不能只盯 CPU。本方案将 REALITY TLS target 指向本机 Nginx8443，并保留 FD/连接保护；是否迁移端口要依据实际流量与授权，只有确认泄漏并取得轮换授权才轮换凭据。

可复用原则：本栈 Trojan fallback、HY2 masquerade 与 REALITY target 都留在本机静态服务。不能为“伪装更像”指向不受控的外部网站再把它当免费中继。Xray出站ACL不代表所有握手/fallback路径都受相同保护。

## 案例2：限速本身也可能让正常用户断连

若旧 Trojan TCP443 的 SYN 激增并持续命中全局新连接限额，即使主机资源充足也会断连。先核对计数器与正常请求失败的时间线；确需迁移且获授权时，只改 Trojan 端口、对应防火墙和两份订阅，配置校验后重启受影响的 Xray，再逐协议复测，避免扰动 Hysteria。

这不是“443必坏”或“10443永不封”的结论。限速要观察命中和正常流量，不能盲目无限放宽；当前模板数值不是通用 DDoS 防护或高并发承诺。变更云规则也要核对权限。

`deploy/migrate-trojan-port.py check/apply/rollback` 只支持这个特定旧布局；先运行 check。配置test+nft原子替换+root备份是约束。回滚要用本次真实备份目录，不抄文档里的作者路径；主机回滚后还要恢复两个远端KV。回到旧443仍可能遇到原流量问题。

## 案例3：线路丢包不是卸载 Codex 能修的

分别采样 Codex 的 CPU/RSS、主机可用内存/OOM、家庭网关/国内 DNS 对照和 VPS 路径，再用真实代理请求对照。如果资源充足而远端链路更差，不应直接卸载 Codex。ICMP 可能受限速，必须结合实际请求，不能把 ICMP 丢包率当精确业务失败率。

只有本次实测支持时才优先选择 HY2 等更稳定的协议，不以重装服务器代替链路诊断。新故障仍重新采样。闲置会话可以在用户允许后退出，无需自动卸载。

## 案例4：订阅刷新不等于服务器更新

若服务器与各订阅入口同格式内容一致，而“更新后好了”与客户端配置重载时间吻合，原因可能是链路抖动后连接/DNS 状态重建。服务端密钥、IP、端口未变时不需要不断下载新节点；频繁依赖手动刷新仍需继续诊断。

`US-Auto` 是 HY2→Trojan→REALITY 顺序 fallback；不是延迟最低自动优选，界面手动固定会改变行为。Clash策略不能通过URI自动搬到小火箭。

## 晚高峰断连：先对照，再调 UDP 缓冲

国内服务正常、只有外网异常时，在同一时段对照主机资源与重启、服务器直连小请求、家庭网关/国内网络，以及隔离客户端逐协议请求。白天测通不能排除晚高峰问题；ICMP 超时也不能换算成业务失败率。记录样本数与耗时分位数，不凭单次延迟或历史累计计数认定根因。

Hysteria/QUIC 还要检查 `/proc/sys/net/core/rmem_max`、`wmem_max` 与 `sudo ss -unamp '( sport = :443 )'` 的 `skmem`。只看 sysctl 不足以证明现有 socket 已扩大。对 `/proc/net/snmp` 的 UDP `RcvbufErrors`、`SndbufErrors` 取 30–60 秒增量；开机以来的累计错误不代表当前仍在丢包。

本模板为 UDP 收发上限设置 7 MiB，依据 [quic-go 的 Linux 缓冲建议](https://quic-go.net/docs/quic/optimizations/)。这是上限，不是每条连接立即占用的内存，也不是跨境拥堵的解决保证。已有节点若低于此值且需要优化，保留更大的已有值，备份原运行值和专用 sysctl 文件；持有与 bootstrap 相同的部署锁，只调整这两个键。提前说明短暂断流，只重启 Hysteria 重新申请缓冲，确认实际 socket、TCP 代理进程未变并逐协议复测。失败恢复本次文件和原值；不要运行完整 bootstrap、改默认缓冲、协议、凭据或防火墙来完成这项调整。Linux 的 `ss` 可能显示约两倍的缓冲核算值，不把它当额外调参目标。

## 日志与正在运行的客户端

使用 `scripts/vps-proxy.ps1 -Action logs` 获取固定类别计数，`status` 只输出服务属性，不再转发原始 journal。`deploy/journal-summary.py` 可通过已授权 SSH 的 stdin 在服务器执行，无需安装；读取失败只报状态，不回显 stderr。`MESSAGE` 可能是字符串、重复字符串数组或 UTF-8 字节数组（包含 ANSI），不能将字节数组直接字符串化。类别可重叠，timeout/断开数不是 HTTP 请求失败数。

摘要中的 `observed_first_utc`/`observed_last_utc` 是这批记录的实际范围，不等于完整日志保留期；`record_limit_reached` 提示可能截断。请求近 7/30 天不代表日志真的保留那么久；空记录或读取失败不等于没有故障。若必须查原始证据，留在服务器或用户独占文件，只输出脱敏结论。

检查 Clash 正在运行的策略组和连接使用的节点，而不只读保存的 YAML。Windows Clash Verge 的实际 Mihomo 命名管道可能与磁盘配置不同；只使用已核验的运行实例接口，以只读方式查询，不开放公网控制端口。控制密钥不输出，管道超时不能认定节点断网。不要覆盖用户配置或清空全部连接“试一下”。

## 恢复边界

先记录此次修改的精确文件、服务与备份。主机快照恢复、软件降级、凭据轮换、云防火墙回退影响不同：向用户说明再操作。不要 `rm -rf` 系统目录或清空 nft ruleset；不要覆盖与本栈无关的SSH/Nginx文件。

完整 bootstrap 备份是部分配置/二进制备份，不会回滚 apt 包、所有sysctl/日志设置、云安全组、DNS、Cloudflare secret/KV 或丢失的SSH权限。首次部署失败优先走先前准备的快照/控制台；已有节点单项修复则恢复对应文件、配置测试、重启受影响服务，再真实客户端验收。续期会短暂重启两个代理服务，一次 `transport closed` 要与重启窗口对齐，不能自动升级成故障。

若确认泄漏，先撤销/轮换凭据再处理 Git 历史；清除当前文件不等于秘密失效。轮换必须同步服务器、Worker secret、两个KV和客户端，并验证旧URL失败。不要未经授权用完整 `rotate` 修无关断连。

本参考保留可复用的判断方法，不附个人实例的运行档案。若排障需要原始证据，先确认本次用户授权，再读取其独占的运行资料；公开 [worklog](../../../worklog/) 只记录通用修复结论，不能上传真实日志、地址、账号、恢复路径或订阅正文。
