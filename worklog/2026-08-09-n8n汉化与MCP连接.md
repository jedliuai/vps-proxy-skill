# n8n 汉化与 MCP 连接

## 1. 做了什么

给 n8n 2.32.6 安装了同版本简体中文前端，同时保留官方后端镜像和原有数据卷。启用了
n8n 官方实例级 MCP，在 Windows 本机建立 SSH 端口转发，并把 `n8n-mcp` 注册到 Codex
全局配置。最终使用 n8n 的个人 MCP Access Token，通过 Windows 用户环境变量交给 Codex；
实际 MCP 握手成功，并能列出 34 个工具。还增加了一个 n8n CLI 包装脚本和一个 MCP 隧道启动脚本。针对 e2-micro 启动
慢的问题，把健康检查从 Node 进程换成轻量 wget，并改为检查数据库 readiness。

## 2. 为什么做

目标是让日常操作尽量使用中文，并允许 Codex 通过 CLI 或 MCP 管理、创建和执行 n8n
工作流。由于当前 n8n 对公网只提供 HTTP，MCP 认证不能直接安全地传输，所以使用 SSH
隧道把 MCP 映射到本机地址。

## 3. 值得记住的决策、坑或技术点

- 中文包来自社区项目，但版本与 n8n `2.32.6` 精确匹配并验证了发布方 SHA-256；只替换
  前端静态文件，没有改后端、SQLite 数据库或凭据。
- 更新 n8n 时不能只更新官方镜像，中文前端也必须更新到相同版本，否则可能出现组件错误。
- n8n 的 OAuth 元数据会校验 MCP 资源地址，因此通过 `N8N_MCP_BASE_URL` 单独声明了
  `http://127.0.0.1:15678`。但当前公网编辑器仍是 HTTP，n8n 的 OAuth 授权会话 Cookie 又强制
  带 `Secure`，浏览器拒绝保存后会立刻报“授权会话失效”。在配置 HTTPS 前，改用个人 MCP
  Access Token 是更可靠的方式；Token 只通过 SSH 隧道传输。
- Codex 配置使用 `bearer_token_env_var = "N8N_MCP_TOKEN"`，没有把 Token 正文写入
  `config.toml`。用户环境变量更新后需要重启 Codex 才能被桌面进程读取。
- 实例级 MCP 不会自动把每个工作流的完整内容暴露出去；工作流仍需单独勾选 MCP 可用。
- 原健康检查每次启动 Node，在低配机器上会与初始化争抢资源。改用 busybox wget 后不再
  堆积额外 Node 进程，并把任务运行器授权宽限期提高到 600 秒。
- 修改前备份了 n8n 数据卷和多份 Compose 配置，均保存在 `/opt/n8n/backups`。

## 4. 一句话亮点

把公网 n8n 变成中文工作台，再用 SSH 加密隧道接入 Codex MCP，让 AI 能安全地直接搭工作流。
