# 公开仓库去除个人运维档案

## 做了什么

把公开工具箱里混入的 31 份历史材料移出当前版本，包括 n8n 部署说明、实例盘点、个人部署方案、旧实施计划和原服务器运维日志。删除前保存了经过校验的私有 Git bundle；原私有仓库没有改动。

保留真正支持搭建、维护和验收的 Skill、部署脚本、Worker、测试及依赖锁文件。README 不再引用旧实例档案或把个人测试成绩放在公共入口；排障参考保留判断方法，删去具体实例日期、资源统计及旧文件链接。

补充了订阅文本、抓包文件、Git bundle、私有目录等忽略规则。Skill 和安全约定明确：真实地址、账号、SSH 路径和恢复位置留在用户独占的仓库外文件，公开总结只写通用结论与脱敏结果。

## 为什么做

公开仓库的职责是让别人的 Codex 能用好这套工具，不是展示作者服务器上曾经做过的所有事情。无关文档会让新用户误判依赖，个人运维记录即便部分脱敏也没有必要长期混在公共入口里。

## 值得记住的决策和坑

不要把测试脚本、依赖锁文件、空白环境模板或兼容性迁移工具误当作垃圾删掉；它们各有调用者或验证用途。可复用经验放进 Skill，不靠堆积原始日志传递经验。

本次检查了全部已跟踪文件、当前可达历史、提交身份和常见隐私模式；已知个人标识与常见凭据扫描没有命中。额外识别的地址与邮箱形态核对后是官方项目链接及合成测试数据。未跟踪忽略文件检查为空，GitHub 没有发布附件、Actions 产物或 Issue/PR 内容需要清理。扫描不是对未知敏感信息的绝对保证。

这是正常的文件清理提交，不是历史抹除：旧公开版本仍可能从 Git 历史或缓存读取，不能把“当前文件删除了”写成“互联网记录已经消失”。如果以后发现真实凭据泄漏，必须单独处理撤销、历史和平台缓存。

验证沿用仓库扫描、静态检查、39 项本地测试和 Skill 校验，并检查所有剩余 Markdown 的本地引用。没有连接 VPS，没有重启节点，也没有改部署程序或 Cloudflare 服务。

## 一句话亮点

公共仓库只分享可复用的方法，不再让下一位使用者翻阅我的服务器日记。
