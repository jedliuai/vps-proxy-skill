## 为什么做

项目想让新用户通过搜索找到，但公开之前必须先切断代码教程与个人运行环境的关联。只删最新 README 中的地址不够，Git 的旧版本和提交元数据同样会被公开。

## 值得记住的决策和坑

用 GEO/SEO 技能里适合 GitHub 的内容结构做优化，没有堆砌隐藏关键词或创建无用的站点 SEO 文件。说明了搜索语境中的“自建 VPN”和实际部署的应用代理之间的区别，不冒充 WireGuard/OpenVPN 或免费机场。

隐私扫描只输出类别与位置，不把敏感值再次写进审计报告。在已扫描对象里没有发现匹配规则的私钥块、完整令牌订阅 URL 或硬编码长凭据；这是扫描结果，不是绝对安全保证。当前 GitHub 没有 PR、Release、Wiki、Pages 或 Actions artifact，但历史提交与作者邮箱仍需要处理。

另外检查了现有8次 Actions 日志，未命中已识别的个人标识或凭据模式。当前文件的已知标识复查及39项测试通过。此后本仓库的新提交使用 GitHub noreply 邮箱，避免继续写入个人邮箱；这不会追溯修改旧提交。

重写历史会改变提交编号，也可能需要处理 GitHub 缓存与旧克隆。在取得这一步的明确同意前保持 Private，不因关键词和标签设置好了就直接公开。不连接或改动线上节点，也不自动轮换正在使用的凭据。

让别人搜得到方法，不让别人顺着方法找到我的服务器。
