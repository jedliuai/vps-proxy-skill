# 美国单实例代理节点

## 做了什么

在现有 Google Cloud 美国小实例上完成了双协议代理：Hysteria2 走 UDP 443，Xray VLESS +
REALITY + Vision 走 TCP 443；用 Cloudflare Worker + 私有 KV 提供主订阅，服务器 8443 提供
独立令牌的备用订阅。Clash Verge 已导入订阅且保留原配置。还补齐了 BBR、nftables、SSH 加固、
证书续期、vnstat、日志限制、私网与 Metadata 出站封锁，并停用了无权限且暴露本地端口的 Ops Agent。

## 为什么做

只有一台美国实例，无法凭空生成日本或新加坡出口，因此目标收敛为“美国单实例尽可能稳定”：
用 UDP 协议应对高延迟和丢包，用 TCP REALITY 应对 UDP 受限，再用一个 Clash 自动切换组降低手工
排障成本。Cloudflare 只提高订阅入口稳定性，不承担节点线路或伪造出口国家。

## 值得记住的决策、坑或技术点

- Xray 当前稳定版的 VLESS 客户端字段必须正确使用 `clients`；字段写错可能通过表面配置加载，
  却在实际连接时把有效 UUID 当成不存在。
- Xray 和 Hysteria 同时使用 443 不冲突，因为一个监听 TCP、一个监听 UDP。
- REALITY 的 TCP 兼容性更适合 ChatGPT 组优先；普通境外流量仍由 `US-Auto` 优先 Hysteria2。
- 故障切换不能只看配置文件：这次真实停止了 Hysteria，确认 Clash 转到 REALITY 并完成请求后才恢复。
- Worker 订阅必须精确令牌路径、私有 KV 和 `no-store`；Cloudflare 不会把美国出口变成亚洲出口。
- 订阅测试文件含完整节点凭据，验收结束必须停止临时核心并删除 YAML、缓存和并发测试文件。
- Google Cloud 的预算和控制面防火墙需要账号级权限；VM 服务账号不能代替用户创建 Billing 预算，
  但主机 nftables 已经完成最小暴露面。

## 一句话亮点

一台美国小主机跑出 UDP/TCP 双通道、自动故障切换和双入口订阅，实测停掉主线路也能无缝走备用。
