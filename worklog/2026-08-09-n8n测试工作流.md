# n8n MCP 测试工作流

## 1. 做了什么

通过已经接通的 n8n MCP 创建了“Codex MCP 连接测试”工作流，放在个人项目中。工作流由
“手动开始”和“生成测试结果”两个节点组成，运行后输出连接状态、中文测试消息、执行时间和来源。
创建前完成了节点级与整图验证，创建后又手动执行了一次，执行 ID 为 `4`，结果为成功。

## 2. 为什么做

需要用一次真实的创建、读取和执行操作验证 Codex 不只是能连上 MCP 端口，而是真的拥有管理
n8n 工作流的完整能力，同时给后续搭建正式自动化留下一个最简单的可参考样例。

## 3. 值得记住的决策、坑或技术点

- 测试流不使用任何第三方凭据，也不向外部服务发送数据，因此可以安全地反复手动运行。
- 按 n8n MCP 的要求，先读取 SDK 参考、数据转换最佳实践和节点类型，再分别验证节点与工作流。
- PowerShell 5.1 对 JSON 请求体的默认编码会损坏中文；发送 MCP 请求时必须明确使用 UTF-8 字节。
- 工作流保持未发布状态，避免测试内容自动运行；它已设置为可通过实例级 MCP 使用。
- 工作流 ID 为 `hC72VVJld8XbvoSO`，首次运行输出了 `status: ok` 和正确的北京时间。

## 4. 一句话亮点

从连接 MCP 到远程创建并跑通第一条中文 n8n 工作流，Codex 已经真正拿到了自动化搭建能力。
