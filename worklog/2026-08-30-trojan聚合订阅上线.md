# Trojan 与聚合订阅上线

## 做了什么

把 Trojan TLS 加到现有美国单实例，并把 Clash YAML 与通用 URI/Base64 两种订阅同步到 Cloudflare KV，发布了按参数或客户端识别格式的统一订阅入口。随后补齐 README、运维文档和安全约定，完成真实 Trojan 代理、端口、防火墙、证书、主备订阅和错误路径验收。

## 为什么做

原有方案只有 Hysteria2 与 REALITY；新增 Trojan 提供 TCP 443 的兼容线路。同时客户端需要同一个入口能协商 Clash 或 URI/Base64 格式，但又不能把订阅凭据和实际节点数据写进仓库。

## 值得记住的决策、坑和技术点

- 一次 HTTP 响应不能同时是 YAML 和 Base64，所以统一入口按 `target` 或 User-Agent 协商，并永久保留两个显式格式入口。
- URI/Base64 是通用 URI 列表，不是旧版 V2Ray Core 的协议兼容承诺；策略、规则和自动切换只放在 Clash YAML。
- 部署时保持 `ROTATE_SECRETS=0`，先备份再更新；订阅只能通过 Git 忽略的临时目录复制，KV 上传后不输出正文、令牌或密码。
- 验证 Trojan 时直接连本机 443 但设置真实 TLS serverName，配合 `mktemp` 与 trap，既能证明链路可用也不会把密码或客户端配置留下来。
- 方案文档必须把“当前状态”和 2026-08-25 的历史处置分开写；否则旧的双协议、旧 443 和旧 ChatGPT 策略会误导后续运维。
- Hysteria2 的 `transport closed` 若集中在部署、续期或人工重启窗口，是正常服务重启痕迹；只有非重启窗口持续出现并影响客户端才升级处理。
- 最终加固把代理服务启动放到 nftables 加载之后，并把 8443 的令牌请求从新 access log 中移除；旧日志仍要当作 root-only 敏感数据，不能为了方便排障扩散或直接自动轮换正在使用的令牌。

## 一句话亮点

一台美国小实例现在有三条可切换线路、一个会“看客户端说话”的订阅入口，并且整个上线过程没有把任何凭据带进代码库。
