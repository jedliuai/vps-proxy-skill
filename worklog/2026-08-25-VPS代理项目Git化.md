# VPS 代理项目 Git 化

## 做了什么

把当前 Google Cloud 实例从 SSH 接入、基础资源盘点、代理部署、Cloudflare 订阅到连接风暴修复的脚本、方案、运维说明和历史记录整理成了一个 Git 项目。新增了 PowerShell 一键运维入口、仓库安全校验、GitHub Actions、忽略规则和安全约定，并创建私有 GitHub 仓库 `jedliuai/vps-proxy-build`。

## 为什么做

之前的操作记录虽然都在本地，但缺少统一版本历史和远端备份。以后换实例、重装服务或再次排障时，如果还靠聊天记录和临时命令拼装，容易遗漏关键的防火墙、凭据轮换和回落保护。Git 化后，每次修改都有依据，也可以从一台新电脑直接恢复工作环境。

## 值得记住的决策、坑或技术点

- 仓库默认设为 Private，但仍按照可能公开的标准处理凭据，不把“私有仓库”当保险箱。
- `.env`、Wrangler 本地状态、Clash YAML、SSH 私钥和服务器生成的凭据全部排除在版本历史之外。
- 部署脚本允许通过环境变量覆盖节点域名、订阅域名和 REALITY 端口，换机不必修改脚本主体。
- 一键运维脚本覆盖检查、部署、轮换、状态、日志和重启；轮换操作必须人工输入确认词，避免误点导致现有订阅立即失效。
- Windows 自带的 `bash.exe` 可能只是不可用的 WSL 入口，因此本地验证脚本优先寻找 Git Bash。
- 提交前同时做凭据模式扫描、Bash/JavaScript/PowerShell 语法检查，并在真实服务器上验证 SSH、服务状态和端口行为。

## 一句话亮点

把一台靠记忆维护的海外小主机，变成了可审计、可恢复、能一键体检的私有基础设施仓库。
