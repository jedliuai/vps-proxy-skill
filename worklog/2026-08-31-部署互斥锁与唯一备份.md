# 部署互斥锁与唯一备份

## 做了什么

给 `server-bootstrap.sh` 增加了非阻塞单实例锁，并把备份目录改成“UTC 时间 + `mktemp` 随机后缀”。同时增加了静态约束和一个从真实脚本提取锁/备份片段的 VPS 临时目录并发测试。

## 为什么做

之前曾因前台等待窗口结束得太早而重复启动部署。两个部署同时备份、安装和写配置会互相覆盖，按秒命名的备份目录也可能刚好相同，所以必须让第二次启动在任何修改前明确退出。

## 值得记住的决策、坑和技术点

锁文件固定保留在 `/var/lock`，但真正的锁绑定在 shell 的 fd 9；进程无论正常结束还是报错退出，描述符都会自动关闭，不能靠“删锁文件”解锁。`flock` 缺失时宁可失败也不能无锁继续。Windows 本机 Git Bash 没有 `flock`，因此真实竞争测试放在 VPS 的 `/tmp` 中运行最小夹具，绝不运行完整部署或碰生产服务。

## 一句话亮点

部署从“别手滑点两次”升级成了“点两次也只会安全地跑一次”。

## 额外记录：家庭网络 TCP 443 验收未通过

家庭独立网络对 TCP 443 的连接在 7 秒超时；同一网络的 2053 约 257ms、8443 约 239ms，均能连通。VPS 的 5 秒采样显示有 7333 个目的端口 443 的 SYN，现行规则对全局新连接限速为 60/s、突发 120；四项服务仍为 active，内存 available 约 444MB，443 监听队列为 0/4096。

此前 loopback Trojan 的 HTTP 204 只能说明本机协议链路正常，不能代替家庭网络公网验收；目前 Trojan 公网验收仍未通过。主入口和两个备用入口合计五个订阅 GET 均为 200，且带 `no-store`。等待用户决定是否改用 10443；在此之前没有改端口、Worker/KV、凭据，也没有重部署。
