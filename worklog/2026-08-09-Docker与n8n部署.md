# Docker 与 n8n 部署

## 1. 做了什么

在 Google Cloud 的 Debian 13 实例上通过 Docker 官方软件源安装了 Docker Engine
29.7.2 和 Docker Compose v5.4.0，并完成 hello-world 验证。随后在 `/opt/n8n` 创建
Docker Compose 部署，启动固定版本 n8n 2.32.6，配置数据持久化、健康检查、日志轮转、
上海时区、执行记录清理和容器自动重启。最后从服务器本机和这台 Windows 电脑分别验证
了健康接口与公网主页，均返回 HTTP 200。

## 2. 为什么做

需要把这台小规格云主机变成一个可以直接使用的自动化工作流平台，同时让部署可以重启
自恢复、数据不会因为重建容器而丢失，也便于以后查看日志、更新和备份。

## 3. 值得记住的决策、坑或技术点

- n8n 固定到 `2.32.6`，没有使用浮动的 latest 标签，避免自动升级带来不兼容。
- 加密密钥单独保存在权限为 `0600` 的 `/opt/n8n/.env`，不能泄露或在已有凭据后更换。
- 端口 `5678` 直接监听公网。为了让纯 HTTP 页面可登录，关闭了 secure cookie；代价是
  网络传输没有 HTTPS 保护，正式使用应尽快加域名和反向代理证书。
- 这台 e2-micro 只有约 964 MiB 内存和很低的持续 CPU 份额，首次解压约 2.48 GB 的镜像
  与数据库迁移耗时较长属于正常现象。已有的 2 GiB Swap 对降低 OOM 风险很关键。
- Docker 发布的端口会走自己的防火墙链，不能只依赖 UFW 的直觉来判断公网是否开放。

## 4. 一句话亮点

一台 1GB 内存的谷歌云小主机，也能稳稳跑起带持久化、健康检查和自动重启的 n8n 自动化平台。
