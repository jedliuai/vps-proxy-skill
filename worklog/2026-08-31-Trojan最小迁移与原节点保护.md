# Trojan 最小迁移与原节点保护

## 做了什么

把 Trojan 从 TCP 443 挪到了 TCP 10443。只改端口、防火墙对应规则和两份订阅，没升级、没装新服务，也没换密码或订阅地址。原 Hysteria2 和 REALITY 在迁移前后都从家里这台电脑测过；Hysteria 的进程号都没变，Xray 因为同时承载 Trojan 和 REALITY，只重启了一次。

Trojan 连续 100 次 Google/GitHub 请求全部成功，用了约 151 秒；两个原节点迁移后各 6 次请求也全部成功，出口都是美国。主、备用订阅一致，完整 Clash 配置用本机 Mihomo 验证通过，统一入口分别测试了 Clash 和 V2Ray 的格式识别。

## 为什么做

不是服务器资源不够，也没有证据需要卸载 Codex。旧 TCP 443 在 5 秒里收到约 7,333 个 SYN，把该端口每秒 60 个的新连接额度挤满了；家里的 SYN 能到服务器却连不上。用户希望别越搞越复杂，所以只尝试一次小范围迁移，先保护原有两个节点。

## 值得记住的决策和坑

没有重跑会安装软件和重建服务的完整部署。迁移前先做 root-only 备份及 Xray/nft 预检查，防火墙用单事务替换，失败或正常终止信号走恢复。对照备份确认 Xray 只有 Trojan port 不同，原 Hysteria 配置、凭据、订阅 URL 文件哈希一致。服务器备份路径与恢复步骤放在运维说明里，敏感正文不进 Git。

订阅先通过家庭客户端测试，再按 Wrangler 流程备份旧内容、同步两份 KV；没有重部署 Worker。统一链接依赖客户端 UA 识别，人工编造的 `ClashVerge` 连写 UA 不在识别规则里会按未知客户端返回 Base64，不能把它误判为订阅损坏；显式格式链接始终保留。

服务 active、本机回环 HTTP 204 和家庭真实可用是三件不同的事。此次补到了家庭短时验收，但没有代替用户测试 ChatGPT 登录、上传、Voice、晚高峰 30 分钟或长期稳定性。如果之后 Trojan 又不好用，就优先选原节点，不叠加线路。

最后整理 Git 时顺手修正了验证范围：只扫描已跟踪文件和未忽略的新文件，不再误扫本机独占的交付目录与嵌套工作树；已经跟踪的文件即使后来被忽略，仍然会扫描。7 项迁移测试、仓库扫描夹具、部署约束及 16 项 Worker 测试通过，代码与恢复文档一起保存在仓库。

## 一句话亮点

这次没有给服务器加装备，只给堵住的端口换了个入口，原节点照常跑，新线路用一百次真实请求说话。
